# יומן ביצוע הדברה — יצחק אחזקות והדברות

מערכת ענן לניהול יומן ביצוע הדברה: עברית RTL, מותאמת לנייד, עובדת גם ללא
קליטה, ומפיקה PDF עברי תקין.

> ## ⚠ לקרוא לפני כל דבר אחר
>
> **1. המערכת אינה מאושרת רשמית** ע"י משרד הבריאות, הרשם לענייני מדבירים
> או כל גוף אחר. היא כלי תיעוד. האחריות על תוכן היומן ועל עמידתו בהוראות
> הרשם היא על המדביר בעל הרישיון.
>
> **2. נוסח הוראת הרשם לא נקרא בזמן הפיתוח.** הכתובת ב-gov.il חסומה ברשת
> סביבת הפיתוח (403 על CONNECT ל-`www.gov.il`). הדרישות יושמו לפי המפרט
> שנמסר (17 סעיפים). **לפני הפעלה בסביבת אמת יש לעבור על
> [`docs/legal-compliance-2026.md`](docs/legal-compliance-2026.md) ולטפל
> בכל הפריטים המסומנים 🔎.**
>
> **3. נספח א׳ ומאגר התכשירים אינם מוטבעים בקוד.** אין במערכת רשימת
> מזיקים או רשימת תכשירים המתיימרת להיות רשמית. יש לטעון אותן ממקור מאומת
> — ראו "טעינת נתוני ייחוס".
>
> **4. קובץ `yomen-hadbara.zip` לא היה זמין בפיתוח.** העיצוב וחלוקת
> השלבים נבנו לפי התיאור במפרט, ולא הועתקו מהמקור. ראו
> [`docs/migration-from-local-html.md`](docs/migration-from-local-html.md)
> → "התאמה למקור".

## מה המערכת עושה

- **ששה שלבי מילוי** המכסים את כל 17 הדרישות המחייבות.
- **שמירה אוטומטית** בכל שינוי — ל-IndexedDB מיד, ולשרת אחרי השהייה קצרה.
- **עבודה ללא קליטה**: הטיוטה נשמרת במכשיר, הפעולות ממתינות בתור,
  והסנכרון חוזר מעצמו — בלי כפילויות.
- **מצב שמירה וסנכרון מוצג תמיד**: נשמר מקומית / ממתין לסנכרון / סונכרן /
  שגיאת סנכרון.
- **חסימת השלמה של יומן חסר**, עם רשימת שדות חסרים בעברית. לחיצה על שגיאה
  מעבירה ישירות לשדה.
- **מספר סידורי עוקב ובלתי חוזר** ברמת העסק, מובטח גם בהשלמות מקבילות.
- **נעילת יומן שהושלם**: אינו ניתן לשינוי או למחיקה. תיקון נעשה בגרסת
  תיקון מקושרת, והמקור נשמר.
- **PDF עברי A4**, RTL, טקסט ניתן לחיפוש, כותרות טבלה חוזרות, QR לאימות.
- **הפרדה מלאה בין עסקים** (Row Level Security), אחסון קבצים פרטי.
- **PWA** הניתנת להתקנה בנייד.
- **תמונות** — צילום או בחירה מהגלריה, דחיסה מבוקרת, שמירה מקומית והעלאה
  לאחסון פרטי כשיש חיבור.
- **ניהול מזמינים ואתרים** — ממלאים אוטומטית את שלבים 1 ו-2 ומצמצמים הקלדה.
- **ייבוא בטוח** מהגרסה המקומית הקודמת, עם תצוגה מקדימה וביטול.
- **מסך בית מודרני** — רשת כפתורים עגולים, ברכה לפי שעת היום, וסטטוס
  סנכרון חי. התגים על הכפתורים סופרים נתונים אמיתיים בלבד.
- **מסלול עבודה** — קווי אחזקה קבועים, סדר ביקורים, „דגשים לביקור הנוכחי”,
  ניווט, התחלת טיפול ופתיחת יומן מתוך הביקור, כולל עבודה ללא קליטה.
  פירוט מלא: [`docs/work-route.md`](docs/work-route.md).
- **ספריות ניסוח שלומדות** — „הוסף מתבנית” בכל שדה טקסט ארוך, וכל ניסוח
  שנכתב ביומן שהושלם נשמר לפעם הבאה. יחד עם מאגר תחנות לאתר, טעינה
  מיומן קודם, אצוות אחרונות, אחריות, סיכום ב-SMS ומסך „בדיקת מערכת” —
  כל אלה הועברו מהגרסה הקודמת. פירוט:
  [`docs/ported-from-legacy-app.md`](docs/ported-from-legacy-app.md).

## ארכיטקטורה

```
┌─ דפדפן / PWA ─────────────────────────────┐
│  React 18 + TypeScript + Vite             │
│  Zod (סכימה מרכזית אחת)                    │
│  IndexedDB — טיוטות, תור סנכרון, קבצים     │
└──────────┬─────────────────┬──────────────┘
           │                 │
   ┌───────▼──────┐  ┌───────▼─────────────────────┐
   │   Supabase   │  │  שירות השרת (Node)          │
   │  PostgreSQL  │  │  • השלמת יומן (Zod + RPC)    │
   │  Auth        │  │  • הפקת PDF (Chromium)       │
   │  Storage     │  │  • פתיחת גרסת תיקון          │
   │  RLS         │  └──────────────────────────────┘
   └──────────────┘
```

**למה Vite ולא Next.js:** אין צורך ב-SSR — המערכת היא כלי שדה שחייב לעבוד
ללא קליטה. SPA + service worker נותן התקנה בנייד ועבודה offline בפשטות
רבה יותר, ובלי שרת render שצריך לתחזק.

**למה שירות Node נפרד:** שלוש פעולות אסור שיתבצעו בלקוח — ולידציה מלאה
לפני השלמה, מספור עוקב אטומי, והפקת PDF. הפונקציות הרגישות במסד פתוחות
ל-`service_role` בלבד, ולכן הלקוח אינו יכול להשלים יומן בעקיפת הוולידציה.
ה-PDF מופק ע"י Chromium מ-HTML עם `direction: rtl` ופונט עברי מוטבע —
זה מה שנותן עברית תקינה, טקסט שניתן לחיפוש ושבירת עמודים נכונה.
`html2canvas` לא בשימוש: הוא מייצר תמונה, והטקסט אינו ניתן לחיפוש.

## הקמת מסד הנתונים

### Supabase (ייצור)
```bash
supabase link --project-ref <ref>
supabase db push                 # מריץ את supabase/migrations בסדר
```
`0000_local_supabase_shim.sql` הוא שכבת תאימות ל-Postgres מקומי בלבד.
`supabase db push` מריץ הכול; אם מריצים דרך הסקריפט, הוא מדלג עליו
אלא אם הועבר `--local`.

### Postgres מקומי (פיתוח ובדיקות)
```bash
npm run db:local         # מפעיל Postgres 16 מקומי על פורט 54329
npm run db:migrate -- --local
npm run db:seed          # נתוני דוגמה בדיוניים
```

### הקמה ראשונית — ארגון ומשתמש מנהל
`organizations` ו-`profiles` אינם נוצרים מהלקוח (בכוונה). ליצירה ראשונית,
עם מפתח service role:

```sql
-- 1. יצירת העסק
insert into public.organizations (name, legal_name, phone, email, address)
values ('יצחק אחזקות והדברות', 'יצחק אחזקות והדברות בע״מ', '04-0000000',
        'office@example.com', 'הכתובת בפועל')
returning id;

-- 2. להזמין את המשתמש דרך Supabase Auth (Dashboard → Authentication → Invite),
--    ואז לשייך אותו לעסק כבעלים:
insert into public.profiles (organization_id, user_id, full_name, email, role)
values ('<organization-id>', '<auth-user-id>', 'השם המלא', 'owner@example.com', 'owner');
```
מכאן, מנהל יכול להוסיף משתמשים נוספים מתוך המערכת.

### אחסון
`0007_storage.sql` יוצר את ה-bucket הפרטי `pest-log-files` ואת מדיניות
הגישה. אם הורצה דרך Postgres מקומי, הקובץ מדלג על עצמו (אין סכמת
`storage`).

## טעינת נתוני ייחוס

**נספח א׳ — רשימת המזיקים:**
```bash
npm run import:pest-catalog -- --file annex-a.csv --org <organization-id> \
  --source "נספח א׳ להוראות הרשם" --source-url "<url>" --verified-at 2026-09-01 --dry-run
```
עמודות: `code,name_he[,name_scientific,group_name,source_name,source_url,verified_at]`

**מאגר התכשירים:**
```bash
npm run import:products -- --file products.csv --org <organization-id> \
  --source "מאגר התכשירים הרשמי" --verified-at 2026-09-01 --dry-run
```
עמודות: `trade_name,active_ingredient_name,active_ingredient_concentration_percent,registration_status[,ready_to_use,registration_number,label_url,valid_until,approved_pests,approved_application_methods,...]`
(רשימות מופרדות ב-`;`)

`--dry-run` מציג מה ייטען בלי לכתוב. כל שורה **חייבת** מקור מידע ותאריך
אימות — הסקריפט מסרב בלעדיהם.

## שירות ההשלמה וה-PDF

```bash
npm run pdf:service
```

| נתיב | מה עושה |
| --- | --- |
| `POST /api/logs/:id/complete` | ולידציה מלאה, השלמה אטומית, הפקת PDF |
| `POST /api/logs/:id/pdf` | קישור חתום ל-PDF (מפיק מחדש אם חסר) |
| `POST /api/logs/:id/correction` | פתיחת גרסת תיקון |
| `POST /api/logs/:id/delivery` | תיעוד מסירה נוספת לאחר ההשלמה |
| `GET /healthz` | בדיקת חיים |

כל נתיב דורש JWT תקף, מאמת שהיומן שייך לארגון של המשתמש, וכפוף ל-rate
limiting. השירות דורש Chromium; אם הוא מותקן במקום לא-סטנדרטי יש להגדיר
`CHROMIUM_EXECUTABLE_PATH`.

## החלטות שכדאי להכיר

| החלטה | למה |
| --- | --- |
| סכימת Zod אחת | אותם כללים בטופס, בשרת, בהשלמה וב-PDF. אין שני מקומות להתעדכן. |
| טיוטה = JSON חופשי | טיוטה חייבת להיות ניתנת לעריכה גם כשהיא חלקית. הוולידציה המלאה רק בהשלמה. |
| ההשלמה ב-RPC אחד | מספור, snapshot, hash, audit — או שהכול קורה, או שדבר לא. |
| `service_role` בלבד להשלמה | הלקוח אינו יכול לעקוף את הוולידציה. |
| snapshot בלתי משתנה | המסמך הקובע הוא מה שהיה בזמן ההשלמה, גם אם המאגר יתעדכן. |
| hash מ-JSON קנוני | אינו תלוי בסדר המפתחות, ולכן ניתן לאימות מחדש. |
| PDF ע"י Chromium | עברית, RTL ושבירת עמודים נכונים; הטקסט ניתן לחיפוש. |
| מפתח אידמפוטנטיות מטביעת אצבע של התוכן | אותו תוכן = אותה פעולה. אין כפילויות ואין דריסה. |
| התנגשות אינה נדרסת בשקט | מוצגת כשגיאת סנכרון, עם ניסיון חוזר ידני. |
| מקור מידע חובה בנתוני ייחוס | אי אפשר להציג רשימה כ"עדכנית" בלי אסמכתה. |

## רישוי ואחריות

המערכת מסופקת לשימוש "יצחק אחזקות והדברות". היא אינה מאושרת רשמית ואינה
מהווה ייעוץ משפטי. האחריות על עמידה בהוראות הרשם היא על המדביר בעל הרישיון.

**במקרה של חשד להרעלה: המרכז הארצי להרעלות — 04-7771900**
