# משחק מקומי לשני שחקנים — הקצאת התקנים וטיפול בניתוק

מסמך זה מתאר איך שני שחקנים מתחברים לאותו מכשיר, איך נאכף הכלל
"התקן אחד שולט בשחקן אחד בלבד", ומה קורה כאשר בקר מתנתק באמצע משחק.

## העיקרון

אין קוד נפרד למשחק המקומי. `MatchSession` מקבל רשימת `PlayerSlot`, וכל slot
מחבר שחקן אחד ל־`PlayerController` אחד:

```
משחק נגד המחשב   [ Slot(home, Composite(מקלדת+מגע)), Slot(away, AIController) ]
שני שחקנים        [ Slot(home, Controller א),        Slot(away, Controller ב) ]
אונליין (שלב ג׳)  [ Slot(home, Controller מקומי),    Slot(away, NetworkController) ]
```

הסימולציה מקבלת `PlayerCommand` בלבד ואינה יודעת מאיזה התקן הוא הגיע.

לפני "מוכנים" אפשר לשנות שם, לבחור צבע חולצה (כל צבע נבחר פעם אחת בלבד),
ולהחליף צדדים. הכרטיס מציג לכל שחקן לאיזה שער הוא תוקף.

## איך נאכף "התקן אחד — שחקן אחד"

| רובד           | המנגנון                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| זיהוי          | `InputDevice.id` ייחודי לכל התקן. שתי מחציות המקלדת הן **שני התקנים לוגיים** (`keyboard-left`, `keyboard-right`), ולכן מקלדת פיזית אחת יכולה לארח שני שחקנים בלי לשבור את הכלל. |
| שני בקרים זהים | `gamepadKey(pad)` משלב את ה־index עם מזהה הבקר, ולכן שני בקרים מאותו דגם מקבלים זהויות שונות.                                                                                   |
| בלובי          | `tryJoin` דוחה התקן שכבר משויך ומציג הודעה.                                                                                                                                     |
| לפני התחלה     | כפתור "מוכנים" נעול כל עוד `device.id` של שני ה־slots זהה או ריק.                                                                                                               |
| בקוד           | `hasDuplicateDevices(slots)` — נבדק ב־`tests/localMultiplayer.test.ts`.                                                                                                         |

## מיפוי המקלדת המפוצלת

| פעולה          | שחקן 1          | שחקן 2                  |
| -------------- | --------------- | ----------------------- |
| תנועה          | `W` `A` `S` `D` | מקשי החצים              |
| ספרינט         | `Shift` שמאל    | `Shift` ימין או `Enter` |
| בעיטה          | `F`             | `K`                     |
| חטיפה          | `G`             | `L`                     |
| שטוחה / מוגבהת | `R`             | `O`                     |

המיפוי ניתן לשינוי במסך ההגדרות ונשמר ב־localStorage.

### keyboard ghosting

מקלדות ממברנה זולות אינן מדווחות על כל צירוף לחיצות בו־זמני; מקשים החולקים שורה
או עמודה במטריצה חוסמים זה את זה. אין דרך לזהות זאת מהדפדפן, ולכן במקום לנסות
לזהות אנחנו **מונעים מראש**: ברירות המחדל מרחיקות את שני המיפויים לשני קצות
המקלדת, ו־`ghostingRisk()` מציג אזהרה אם שינוי ידני מכניס את שני השחקנים
לאותו אזור. `findConflicts()` מתריע על מקש שמשויך ליותר מפעולה אחת.

## מגע משותף

במצב אופקי בלבד, שני אזורי מגע עצמאיים:

- `touch-left` — חצי שמאל, `touch-right` — חצי ימין. צדדים **פיזיים**, לא מושפעים
  מכיוון ה־RTL של המסמך (`dir="ltr"` על שכבת הפקדים).
- לכל אזור ג׳ויסטיק, בעיטה, ספרינט, חטיפה ומתג סוג בעיטה משלו.
- **כל pointer שייך לפקד שבו התחיל** עד `pointerup` או `pointercancel`. אצבע של
  שחקן אחד אינה יכולה לגנוב את הג׳ויסטיק של השני, ואצבע שמורמת אינה משחררת
  בעיטה של מישהו אחר. נבדק ב־`tests/touchPointers.test.ts`.
- `touch-action: none` מוגדר על אזור המשחק ועל הפקדים בלבד.

## תרשים זרימה — ניתוק בקר

```
        ┌──────────────────────────────────────────┐
        │  בכל frame בזמן משחק:                    │
        │  session.findDisconnected()              │
        └────────────────────┬─────────────────────┘
                             ▼
                ┌────────────────────────┐
                │  יש slot מנותק?        │
                └──┬──────────────────┬──┘
                לא │                  │ כן
                   ▼                  ▼
        ┌──────────────┐   ┌──────────────────────────┐
        │ ממשיכים      │   │ pause(showScreen=false)  │
        └──────────────┘   │ מסך "אמצעי השליטה        │
                           │ התנתק" + שם השחקן        │
                           └────────────┬─────────────┘
                                        ▼
                           ┌──────────────────────────┐
                           │ pollReconnect() בכל frame│
                           │ • refreshGamepads()      │
                           │ • rebind(padIndex) אם    │
                           │   הבקר חזר ב־slot אחר    │
                           └────────────┬─────────────┘
                                        ▼
                      ┌─────────────────────────────────┐
                      │  הבקר חובר מחדש?                │
                      └──┬───────────────────────────┬──┘
                      כן │                           │ לא
                         ▼                           ▼
            ┌────────────────────────┐   ┌────────────────────────┐
            │ "המשך משחק" נפתח       │   │ הכפתור נשאר נעול       │
            │ → resume() + ספירה     │   │ המשחק ממתין            │
            └────────────────────────┘   └────────────────────────┘
                         │
                         │  לחלופין, ורק ביוזמת המשתמש:
                         ├─► "העבר את השחקן לשליטת המחשב" → AIController
                         └─► "יציאה לתפריט"
```

**השליטה לעולם אינה עוברת ל־AI באופן אוטומטי.** זו פעולה מפורשת של המשתמש בלבד.

הבקר מזוהה מחדש לפי `deviceId` ולא לפי ה־index, כי דפדפנים עשויים להחזיר בקר
שחובר מחדש ל־slot אחר. `HumanGamepadController.rebind()` מעדכן את ה־index
ומאפס את מצב הלחיצות, כדי שבעיטה שנטענה לפני הניתוק לא תישאר תקועה.

## מה קורה בפוקוס ובמעבר לרקע

| אירוע                     | התנהגות                                         |
| ------------------------- | ----------------------------------------------- |
| `blur` בחלון              | ניקוי מצב המקלדת, איפוס כל ה־Controllers, השהיה |
| `visibilitychange` להסתרה | עצירת לולאת הרינדור והאודיו, השהיה              |
| חזרה מהסתרה               | איפוס ה־accumulator, חידוש הלולאה               |
| `pointercancel`           | ה־pointer משוחרר מהפקד שהחזיק בו                |
| מעבר לאנכי בטלפון         | הודעת סיבוב + השהיה                             |
