# צינור הנכסים הגרפיים

## ההחלטה, ולמה

ב־STANGA אין נכסי אמנות חיצוניים. כל טקסטורה, כל דמות, כל צליל וכל אייקון
נוצרים בזמן ריצה מתוך קוד שנמצא במאגר. הרשימה המלאה — ובפועל, היעדרה —
ב־[`THIRD_PARTY_ASSETS.md`](../THIRD_PARTY_ASSETS.md).

זו אינה החלטה אסתטית אלא החלטת רישוי. אסור להעתיק נכסים מ־FIFA, מ־EA, מ־PES
או מכל משחק מסחרי אחר, ובסביבת הפיתוח הזאת גם אין גישה לספריית נכסים
מורשית להורדה. האפשרויות היו שתיים: לייצר הכול בקוד, או להצהיר על "איכות
AAA" ולא לספק אותה. נבחרה הראשונה.

## מה הושג בפועל

| שכבה            | מה יש                                                                         |
| --------------- | ----------------------------------------------------------------------------- |
| חומרים          | PBR (metallic-roughness) על הקרקע, הקירות, הגדר, המסגרת, הרשת, הכדור והדמויות |
| מפות            | albedo, normal ו־metallic-roughness — כולן משורטטות ב־Canvas 2D               |
| תאורה           | שמש directional + hemispheric ambient + IBL מצולם מכיפת השמיים של הסצנה       |
| Tone mapping    | ACES, עם exposure ו־contrast                                                  |
| Post-processing | FXAA, bloom, vignette, sharpen, ו־SSAO ברמה המרבית                            |
| צללים           | shadow map עם PCF, 512 עד 4096 לפי הרמה                                       |
| LOD             | פרטי הדמות (שיער, נעליים, צוואר) נכבים מעבר למרחק שנקבע ברמת האיכות           |
| קהל             | thin instances של צללית אחת — draw call אחד לכל הקהל                          |
| Presets         | נמוכה / בינונית / גבוהה / מרבית, עם מסך גרפיקה שמודד בזמן אמת                 |

### איך נוצרת תאורת הסביבה בלי קובץ HDR

`ReflectionProbe` מצלם פעם אחת את כיפת השמיים ואת הרקע הרחוק לתוך cube map
בגודל 128, וה־cube map הזה הופך ל־`scene.environmentTexture`. זהו צילום אמיתי
של השמיים של המשחק: האספלט קולט את הכחול שמעליו, והמסגרת קולטת את צד השמש.

## מה **לא** הושג — במפורש

**זו אינה איכות FIFA, ואין לטעון שהיא כן.** הפער אינו בקוד הרינדור אלא בנכסים:

1. **אין דמויות rigged.** הדמות בנויה מפרימיטיבים (קפסולות, גלילים ותיבות)
   שמסובבים סביב מפרקים, לא ממודל עם שלד ו־skinning. אין blend tree, אין IK
   ואין motion capture. האנימציה היא מכונת מצבים פרוצדורלית
   (`PlayerAnimator`), והיא קריאה — אבל היא לא נראית כמו אדם שצולם.
2. **אין טקסטורות מצולמות.** מפה שמשורטטת ב־Canvas בגודל 512–1024 אינה
   תחליף ל־scan של אספלט ב־4K.
3. **אין IBL מסוג HDR מסונן כראוי.** ה־cube map מה־probe אינו prefiltered
   ל־roughness; הטשטוש מגיע משרשרת ה־mip ולא מ־convolution. על משטח מחוספס
   זה נראה נכון, על משטח חלק פחות.
4. **אין פנים, אין שיער אמיתי, אין בד מדומה, אין דשא/אספלט עם parallax.**

הפער הזה ייסגר רק ברכישת נכסים בעלי רישיון או בהזמנת נכסים מקוריים. השלבים
לכך מתוארים למטה, והקוד בנוי כדי לקבל אותם.

## איך להכניס נכס אמיתי כשיהיה

1. **רישיון לפני קובץ.** לוודא שימוש מסחרי + הפצה, לשמור את הרישיון במאגר,
   לרשום שורה ב־`THIRD_PARTY_ASSETS.md`.
2. **פורמט.** glTF 2.0 בינארי (`.glb`) לדמויות ולאביזרים; KTX2/Basis
   לטקסטורות; `.env` (של Babylon) ל־IBL. כולם נתמכים ב־Babylon ללא תוספים.
3. **דמות.** שלד עם שמות מפרקים סטנדרטיים, אנימציות ניטרליות (idle, ריצה,
   ספרינט, בעיטה, מסירה, הקפצה, חטיפה, חגיגה), ו־3 רמות LOD.
   נקודת החיבור בקוד: `PlayerView` בונה היום את הגאומטריה בעצמו — להחליף את
   הבנייה בטעינת `.glb` ואת `PlayerAnimator` במיפוי מצב→אנימציה. הממשק
   (`updateVisual(state, inputs, dt)`) לא משתנה, ולכן שום דבר אחר לא נוגע בזה.
4. **תקציב.** דמות: עד 12k משולשים ב־LOD0, עד 3 חומרים, טקסטורות 1024.
   מגרש וסביבה: עד 60k משולשים בסך הכול.
5. **אימות.** `npm run build` חייב להישאר מתחת ל־8MB נכסים מוקדמים, ומסך
   הגרפיקה חייב להראות זמן פריים מתחת לתקציב במכשיר היעד.

## תקציבי ביצועים

היעד הוא 60 פריימים לשנייה, כלומר 16.7 מילישניות לפריים, בכל ארבע הרמות
על חומרת היעד שלהן.

| רמה     | חומרת יעד                   | מה נכבה כדי לעמוד בזה              |
| ------- | --------------------------- | ---------------------------------- |
| נמוכה   | טלפון בן 4–5 שנים           | צללים, IBL, post, קהל, טבעות סימון |
| בינונית | טלפון עדכני / מחשב נייד ישן | bloom, SSAO                        |
| גבוהה   | מחשב עם GPU נפרד            | SSAO                               |
| מרבית   | מחשב חזק                    | —                                  |

**המספרים האלה הם יעדים, לא מדידות.** סביבת הפיתוח של הפרויקט מריצה דפדפן
על SwiftShader (רינדור בתוכנה, בלי GPU) ומגיעה ל־4–6 פריימים לשנייה בכל רמה.
אפשר היה לאמת שם נכונות, היעדר שגיאות וסנכרון — **אי אפשר** היה למדוד 60
פריימים לשנייה, ולכן לא נטען שנמדדו. מסך הגרפיקה במשחק מציג את המדידה
האמיתית של המכשיר שמריץ אותו, וזו התשובה היחידה שאפשר לסמוך עליה.
