# יומן הדברה – יצחק הדברות

אפליקציית PWA בעברית מלאה (RTL) לתיעוד עבודת הדברה בשטח: אשף יומן בשמונה שלבים,
ניהול לקוחות, מסלול עבודה, מאגר חומרים ותבניות, חתימות דיגיטליות והפקת מסמך להדפסה/PDF.

## הפעלה מהירה

```bash
npm install
npm run build     # בניית האפליקציה
npm start         # שרת על http://localhost:3000
```

פיתוח עם רענון חם:

```bash
npm run dev:api   # שרת ה-API על פורט 3000 (חלון נפרד)
npm run dev       # Vite על פורט 5173, עם proxy ל-/api
```

בדיקות ואיכות:

```bash
npm run verify    # typecheck + lint + בדיקות יחידה + build
npm test          # בדיקות יחידה בלבד (Vitest)
npm run e2e       # בדיקות קבלה בדפדפן (דורש: npm i -D playwright, ושהשרת פועל)
                  # 69 בדיקות: זרימת יומן, חיפוש חומרים, מסלול, נגישות
```

בנייה עצמאית ללא שרת (לאירוח סטטי או להדגמה) — ללא סנכרון וללא service worker,
כל הנתונים נשמרים בדפדפן בלבד:

```bash
VITE_STANDALONE=1 npx vite build --base=./ --outDir=dist-demo
```

משתני סביבה: `PORT` (ברירת מחדל 3000), `DATA_DIR` (ברירת מחדל `./data`),
`VITE_STANDALONE=1` (בנייה ללא שרת).
ל-`npm run e2e` אפשר להגדיר `BASE_URL` ו-`CHROME_PATH`.

## ארכיטקטורה

| שכבה | טכנולוגיה | תפקיד |
| --- | --- | --- |
| ממשק | React 19 + TypeScript + Vite | אשף היומן והמסכים |
| מצב | Context יחיד (`src/state/store.tsx`) | מקור אמת אחד לכל הנתונים |
| אחסון מקומי | IndexedDB (נפילה ל-localStorage ולזיכרון) | שמירה אוטומטית ועבודה ללא רשת |
| סנכרון | תור עמיד (`src/lib/sync.ts`) | שליחה לשרת כשחוזרת הרשת |
| שרת | Node 22 + `node:sqlite`, ללא תלויות | API, ולידציה בצד שרת, הגשת הבנייה |
| PWA | manifest + service worker | התקנה למסך הבית ועבודה במצב לא מקוון |

מקור אמת אחד: שדה החיפוש, התבנית ורשומת היומן קוראים וכותבים לאותו אובייקט ב-store.
אין state כפול בין הרכיבים.


## משתמשים, עסקים והרשאות

המערכת רב-עסקית: כל עסק הוא דייר נפרד, ונתוניו אינם נגישים לעסק אחר.

### התפקידים

| תפקיד | מה מותר |
| --- | --- |
| מנהל מערכת | אישור עסקים, ניהול מנויים. **אינו רואה** לקוחות, יומנים או חתימות של עסקים |
| בעל עסק | גישה מלאה לנתוני העסק, הוספת עובדים וניהול הרשאות |
| מדביר | תיעוד מלא, חתימה והפקת מסמכים |
| עובד שטח | תיעוד בשטח |

### זרימת ההצטרפות

1. מדביר נרשם במסך "רישום עסק חדש" עם פרטי העסק.
2. הסטטוס הוא "ממתין לאישור": הוא יכול להתחבר ולראות את מצבו, אך לא לתעד.
3. מנהל המערכת מאשר במסך "ניהול עסקים" וקובע "שולם עד".
4. מרגע האישור העסק פעיל.

מנוי שפג **אינו חוסם** את העסק: הוא עובר לקריאה בלבד. התיעוד נשאר נגיש
ואינו נמחק. השעיה או דחייה מנתקת מיד את כל משתמשי העסק.

### יצירת מנהל מערכת

```bash
npm run create-admin -- you@example.com 'סיסמה-חזקה' 'השם שלך'
```

הסיסמה אינה נשמרת בקוד או בלוג — רק הגיבוב שלה נשמר במסד.

### חשבונות לפיתוח

```bash
npm run seed:dev      # יוצר מנהל מערכת, עסק מאושר, בעלים ועובד
```

הסיסמאות שם מיועדות לפיתוח בלבד. אין להשתמש בהן בסביבה אמיתית.

### אבטחה

- סיסמאות בגיבוב scrypt עם מלח לכל משתמש; השוואה בזמן קבוע.
- אסימוני התחברות נשמרים כגיבוב בלבד.
- נעילת חשבון אחרי 8 ניסיונות כושלים למשך 15 דקות.
- כל בקשת API נבדקת מול בעלות העסק — גם קריאה וגם כתיבה.
- הנתונים המקומיים מופרדים לפי משתמש, כך שעל מכשיר משותף
  עובד אחד אינו רואה את מה שנשמר עבור קודמו.

**חובה להגיש את המערכת ב-HTTPS בלבד.** בלעדיו האסימונים והסיסמאות
עוברים בטקסט גלוי.

**הערה משפטית:** אחסון נתוני לקוחות של עסקים אחרים הופך אותך למחזיק
מאגר מידע, עם חובות לפי חוק הגנת הפרטיות. יש להסדיר זאת לפני גביית תשלום.

## ייצוא לאפליקציה לנייד

יש שני מסלולים. שניהם מריצים את אותו קוד.

### מסלול א': התקנה מהדפדפן (PWA) — מהיר, בלי חנויות

האפליקציה כבר PWA מלא: manifest, service worker, אייקונים ועבודה אופליין.
צריך רק לארח אותה בכתובת **HTTPS**:

```bash
npm run build
npm start          # או כל אירוח סטטי של dist/ מול שרת ה-API
```

אחרי שהאתר באוויר:

- **אנדרואיד (Chrome):** תפריט ⋮ ← "התקנת אפליקציה".
- **אייפון (Safari):** שיתוף ← "הוספה למסך הבית". חובה Safari; בכרום באייפון אין התקנה.

מה מקבלים: אייקון על מסך הבית, פתיחה במסך מלא בלי סרגל הדפדפן, ועבודה אופליין
מלאה. מה לא מקבלים: נוכחות ב-Google Play / App Store, והתראות דחיפה באייפון
מוגבלות.

### מסלול ב': אפליקציה מקומפלת לחנויות (Capacitor)

הפרויקט מוגדר ומוכן. תיקיות `android/` ו-`ios/` אינן נשמרות בגיט ונוצרות בפקודה אחת.

```bash
npm install
VITE_API_BASE=https://your-server npm run build   # כתובת השרת, חובה כאן
npm run mobile:add:android                        # פעם אחת
npm run mobile:assets                             # אייקונים ומסכי פתיחה
npm run mobile:open:android                       # נפתח ב-Android Studio
```

מתוך Android Studio: Build ← Build APK, או Generate Signed Bundle להעלאה ל-Play.

ל-iOS נדרש Mac עם Xcode:

```bash
npm run mobile:add:ios
npm run mobile:assets
npm run mobile:open:ios
```

אחרי כל שינוי בקוד: `npm run mobile:sync`.

**חשוב — כתובת השרת:** באפליקציה מקומפלת ה-webview רץ מ-`capacitor://localhost`,
ולכן נתיב יחסי כמו `/api/sync` לא יגיע לשרת. חובה לבנות עם `VITE_API_BASE`
שמצביע על כתובת השרת האמיתית. לאפליקציה ללא שרת כלל:
`VITE_STANDALONE=1 npm run build` — אז הנתונים נשמרים במכשיר בלבד.

### מה צריך בנוסף לפרסום בחנויות

| דרישה | אנדרואיד | iOS |
| --- | --- | --- |
| חשבון מפתח | Google Play, תשלום חד-פעמי | Apple Developer, תשלום שנתי |
| מכונת בנייה | כל מחשב עם Android Studio | Mac עם Xcode בלבד |
| חתימה | keystore משלך | תעודות ו-provisioning של Apple |
| מדיניות פרטיות | נדרשת | נדרשת |

הערה: האפליקציה אוספת שמות לקוחות, כתובות, טלפונים וחתימות. לפני פרסום בחנות
יש להצהיר על כך, ולוודא עמידה בחוק הגנת הפרטיות.

## ייבוא מאגר התכשירים המורשים

המקור הרשמי: <https://www.gov.il/he/Departments/DynamicCollectors/pesticides-database>

מאגר הנתונים הפתוח: <https://data.gov.il/he/datasets/ministry_of_the_environment/domestic_pesticides>

**המאגר כבר מיובא: 157 תכשירים**, נכון ל-07/10/2026.

### איך מעדכנים

1. מורידים את הרשימה מהמאגר (XLSX, CSV או JSON).
2. מריצים:

```bash
npm run import:pesticides -- --file ~/Downloads/pesticides.xlsx
npm run build
```

נתמכים XLSX, CSV ו-JSON. קריאת ה-XLSX מיושמת ללא תלויות חיצוניות.
שורות כותרת ומקור שלפני הטבלה מזוהות ומדולגות אוטומטית.

הסקריפט מזהה את העמודות לפי מילות מפתח, בעברית ובתעתיק לטיני, ולכן אינו
תלוי בשם עמודה מדויק. אם המבנה השתנה:

```bash
npm run import:pesticides -- --file <קובץ> --inspect
```

הפקודה מציגה את העמודות הזמינות עם דוגמת ערך, ואת מה שזוהה אוטומטית.
אפשר למפות ידנית:

```bash
npm run import:pesticides -- --file <קובץ> \
  --map tradeName=שם_התכשיר,registrationNumber=מספר_רישום,activeIngredient=חומר_פעיל
```

אפשר גם למשוך ישירות מכתובת: `--url <כתובת JSON או CSV>`.

### מה נכנס ומה לא

| מהמאגר | מהתווית בלבד |
| --- | --- |
| שם התכשיר | מינונים |
| מספר רישום | אזהרות לאדם ולבעלי חיים |
| חומר פעיל ואחוזו | סיכונים לסביבה |
| תוארית | הוראות ללקוח |
| מזיקים מאושרים | זמן כניסה מחדש |
| תוקף רישום | |
| בעל הרישום | |
| קישור לתווית | |

לכן **כל תכשיר מיובא מסומן "מידע יושלם בהמשך"**. אין בכך כדי לחסום עבודה:
אפשר לבחור אותו, לתעד ולשמור — אך המינונים והאזהרות חייבים להיות מושלמים
מהתווית הרשמית לפני הסתמכות מקצועית.

אחוז החומר הפעיל נקרא מהמקור ואינו מנוחש. ערך שאינו קיים מסומן "לא הוזן".

ארבעת התכשירים שהוזנו ידנית (דרגון, דרקר 10.2, פסטיון פלוס פסטה, בלוקיון פלוס)
גוברים על המאגר המיובא ושומרים על תבניות הטיפול שלהם.

### חיפוש

החיפוש פותח תוצאות כבר מהאות הראשונה, ללא רשימה נפתחת לפני הקלדה.
אפשר לחפש לפי שם מסחרי, שם החומר הפעיל או מספר רישום. עם בחירת התכשיר
החומר הפעיל, אחוזו ומספר הרישום מתמלאים אוטומטית בכרטיס היומן.

## מצב נתוני התוויות — חשוב

מספרי הרישום, החומרים הפעילים והקישורים לתוויות הוזנו לפי מה שנמסר על ידי המשתמש.
**מינונים, אזהרות, הוראות ללקוח וזמני כניסה מחדש לא הוזנו**, משום שלא ניתן היה לקרוא
את התוויות הרשמיות. כל ערך כזה מסומן `לא הוזן`, וכל ארבעת החומרים מסומנים
`unverified` ("מידע יושלם בהמשך"). אין להסתמך עליהם מקצועית עד להשלמה מהתווית
הרשמית העדכנית ולסימון אימות.

| חומר | מס' רישום | חומר פעיל | מה חסר |
| --- | --- | --- | --- |
| דרגון | 640 | Bifenthrin 9.6% | מינונים, אזהרות, זמן כניסה, הוראות ללקוח |
| דרקר 10.2 | 569 | Cypermethrin 10%, Tetramethrin 2%, PBO 10% | טווחי מינון לפי סוג משטח, אזהרות, זמן כניסה |
| פסטיון פלוס פסטה | 584 | Brodifacoum 0.005%, Denatonium Benzoate 0.001% | כמות לתיבה, נוסח הוראות הבטיחות להצבת פיתיון |
| בלוקיון פלוס | לא הוזן | לא הוזן | כל נתוני התווית |

פסטיון פלוס פסטה מוגדר כטיפול בפיתיון: **אין לו זמן כניסה מחדש של ריסוס**, אלא
הוראות בטיחות להצבת פיתיון בתיבות.

## הבהרה משפטית

המערכת בנויה לתיעוד עבודת הדברה לפי הנתונים שהוזנו בה. היא אינה מהווה אישור חוקי
ואינה קובעת עמידה בדרישות הדין. חובה לפעול לפי הדין החל, תנאי רישיון המדביר
והתווית הרשמית העדכנית של כל תכשיר.

## עיצוב ומקוריות

הממשק, הניסוחים, האייקונים והאנימציות נכתבו במיוחד לאפליקציה זו. לא נעשה שימוש
בלוגו, בשם מסחרי, בטקסטים, בגרפיקה או בקוד של אפליקציה אחרת.
