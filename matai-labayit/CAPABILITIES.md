# יכולות: מה עובד עכשיו, מה דורש שרת AI, ומה המגבלות

שלוש רמות:

1. **במכשיר בלבד** – בלי אינטרנט, בלי חשבון, בלי שרת. תמיד זמין.
2. **שרת AI בניהול עצמי** (`server/`) – מודלים פתוחים שרצים אצלכם (SAM, ISNet, MiDaS). **אין מפתחות API ואין צד שלישי.**
3. **ספקים חיצוניים** (אופציונלי) – remove.bg, או שירות "השתלבות" גנרטיבי. המפתחות נשמרים רק בשרת (משתני סביבה), **אף פעם לא בקוד האפליקציה**.

תמונת הבית נשלחת לשרת רק אם המשתמש הפעיל "עיבוד בענן" בהגדרות, אישר את ההסבר, **ובנוסף** אישר בעורך את
"שליחת תמונת החדר לעיבוד" (פעם אחת לכל כניסה לעורך). בכל מקום יש חלופה מקומית ("זיהוי מקומי").

## 1. במכשיר בלבד

| יכולת | איך זה עובד |
|---|---|
| צילום והעלאה | כפתורים נפרדים: "צלם חדר", "העלה תמונת חדר", "צלם מוצר בחנות", "העלה תמונת מוצר". בדיקת תמונה לפני עיבוד: סיבוב, חיתוך, החלפה, ובדיקת איכות (חשוכה/בהירה מדי, מטושטשת, השתקפות, רזולוציה נמוכה) עם הנחיה. |
| כמה זוויות למוצר | צילום/העלאה של זוויות נוספות, בחירת הזווית שמתאימה לנקודת המבט בחדר, והחלפת זווית גם אחרי ההצבה. |
| לא מאבדים עבודה | טיוטות (חדר/מוצר) נשמרות תוך כדי – גם אם יצאתם באמצע שיחה או האפליקציה נסגרה; באנדרואיד – שחזור צילום שהמערכת "הרגה" את האפליקציה בזמנו (`getPendingResultAsync`). בעורך: שמירה רציפה, ביטול/ביצוע מחדש, גרסאות בלי דריסה. |
| הסרת רקע מקומית | `imaging/cutout.ts → autoMask`: מודל צבעי רקע (משולי המלבן) ומוצר (מהמרכז) במרחב Lab, מילוי מהשוליים. **הסרת צל הרצפה של החנות** (`removeGroundShadow`) – כדי שהצל ייווצר מחדש בחדר. תיקון במברשת מחיקה/שחזור, ביטול צעד. |
| הודעה על צילום קשה | בבדיקת התמונה: השתקפויות/ברק, חשוכה, שרופה, מטושטשת, רזולוציה נמוכה. אחרי החיתוך: "המוצר נחתך בשולי התמונה", "לא זוהה מוצר ברור", "כמעט לא הוסר רקע". תמיד עם הנחיה מה לעשות – ואפשר להמשיך ולתקן ידנית. |
| מבנה החדר | **מישורים** (קיר/רצפה בארבע פינות, עם רוחב/גובה בס״מ לגודל אמיתי) ו**חפצים קיימים** (סימון בנגיעה לפי צבע או במברשת, "+ חלק" לרגליים וכו'). |
| הצבה בפרספקטיבה | גרירה, צביטה, סיבוב, ידית פינה; הטיה תלת־ממדית; **פרספקטיבה חופשית בארבע פינות**; **הצמדה למישור** – טלוויזיה/תמונה/מדף "נצמדים" לקיר ושטיח לרצפה, והגודל נגזר ממידות המישור. |
| גודל | מידות מוצר + "קנה מידה" (קו על חפץ ידוע) או מישור עם מידות ← גודל אמיתי. בלי מידות: תווית "גודל משוער". |
| השתלבות בחדר | מדידת הסצנה בחנות ובסביבת המוצר בחדר (חשיפה ואיזון לבן – gray world, ניגודיות, חדות, רעש) ← התאמת בהירות/גוון/ניגודיות, טשטוש לחדות החדר וגרעיניות. **מחוון "נאמנות למוצר המקורי ↔ שיפור השתלבות"** (ברירת מחדל קרובה לנאמנות). צורת המוצר והפרטים לא משתנים – רק תיקון צבע גלובלי. |
| צל | צל מגע (בסיס) + **צל מוטל מצללית המוצר עצמו** (כיוון, אורך, עוצמה, ריכוך); צל קיר לחפצים תלויים. |
| הסתרה | מוצר שמאחורי רהיט שסומן (לפי קו הבסיס שלהם בתמונה) מוסתר אוטומטית; **מברשת "הסתרה"** ידנית לכל מקרה אחר. |
| תוצאות לבחירה | ארבע גרסאות מוכנות (נאמן למקור / מאוזן / משתלב / אור מהחלון) עם תצוגה מקדימה – בוחרים ומכווננים. |
| משטחים: צבע | "טבעי" (שומר צללים ומרקם), הכפלה, כיסוי. |
| משטחים: פרקט, אריחים, חיפוי, טפט | דוגמה מצילום החנות (עם "ניקוי תאורת החנות"), פרספקטיבה מלאה (הומוגרפיה), גודל אריח/לוח, כיוון הנחה, ישר/בהזחה, פוגות, **שונות טבעית בין לוחות** (בלי חזרה מלאכותית), **שמירת האור והצללים של החדר** – כולל כתמי שמש (hard light), בלי שהמרקם הישן (פוגות אריחים) יבצבץ. **פתחים** (חלון/דלת) שלא מכוסים. התאמת חשיפה/איזון לבן לחדר עם מחוון נאמנות. |
| תאורה | הילת אור של גוף תאורה – **מסומנת "המחשה בלבד"**. |
| וילונות | קפלים (מספר ועומק) מעל הבד שצולם. |
| השוואה וייצוא | לפני/אחרי, זו לצד זו, גרסאות; ייצוא עם סימון "הדמיה להמחשה". |
| פרטיות | מחיקת תמונות, מוצרים, חדרים וכל הנתונים; ניקוי קבצים יתומים. |

## 2. שרת AI בניהול עצמי (בלי מפתחות)

```bash
cd server
npm install              # onnxruntime-node + sharp
npm run models           # מוריד ~350MB מודלים פתוחים ל-server/models (פעם אחת)
npm start                # http://localhost:8787
npm test                 # בדיקות – כולל הרצת המודלים האמיתיים אם הורדו
```

| יכולת | מודל | איפה באפליקציה | מצב |
|---|---|---|---|
| הסרת רקע מדויקת | **ISNet** (general-use) לשוליים רכים + **SAM ViT‑B** שבוחר *איזה* אובייקט במלבן הוא המוצר (מדפים/מוצרים אחרים נשארים בחוץ); רכיבים קטנים צמודים (רגליים) נשמרים | חיתוך מוצר ← "הסרת רקע AI" | **עובד ונבדק** (ספה באולם תצוגה עם מדפים, כורסה ומנורה ברקע). שולח רק את תמונת המוצר. |
| בחירה בנגיעה | **SAM** (נקודה → מסכה, ואז סבב שני עם מלבן להשלמת אותו חפץ) | סימון חפצים קיימים, זיהוי קיר/רצפה, "הוספת אזור" | **עובד ונבדק** (שולחן קפה, רגליים, רצפה, קיר עם חלון). |
| מפת עומק | **MiDaS small** | – | נקודת קצה `/v1/depth` קיימת ונבדקה; **האפליקציה עוד לא משתמשת בה** (ההסתרה מבוססת על קו הבסיס של החפצים). |

## 3. ספקים חיצוניים (אופציונלי, מפתחות רק בשרת)

| יכולת | משתנה סביבה | מצב |
|---|---|---|
| הסרת רקע – remove.bg | `REMOVE_BG_API_KEY` | ממומש; **לא נבדק עם מפתח אמיתי** בסביבה הזו. |
| "השתלבות" גנרטיבית (אור, השתקפויות, צל רך) | `HARMONIZE_SERVICE_URL` (+`HARMONIZE_SERVICE_TOKEN`) | **ממשק בלבד – לא מחובר מודל.** האפליקציה שולחת לשרת את ההדמיה ואת מסכת המוצר (`protect`); השרת מעביר לשירות `POST {image, mask, strength}` ← `{image}`, ואז **מדביק בחזרה את פיקסלי המוצר המקוריים** לפי `protect`, ומגביל את העוצמה ל-0.6 – כך שמודל יצירת תמונה יכול לשנות רק סביבה/צל/שוליים ולא את דגם המוצר. באפליקציה: ייצוא ← "השתלבות AI" (מופיע רק כשהשרת מדווח שהשירות מוגדר). |
| סגמנטציה חיצונית | `SEGMENT_SERVICE_URL` (+`SEGMENT_SERVICE_TOKEN`) | חלופה ל-SAM המקומי; לא נבדק. |

### ממשק השרת

| נתיב | גוף הבקשה | תשובה |
|---|---|---|
| `GET /v1/health` | – | `{ok, capabilities: {removeBackground, segment, depth, harmonize, models, mock}}` |
| `POST /v1/remove-background` | `{image, box?}` (box מנורמל 0..1) | `{image: PNG שקוף, method}` |
| `POST /v1/segment` | `{image, points:[{x,y,label}], box?}` | `{mask: PNG, score}` |
| `POST /v1/depth` | `{image}` | `{depth: PNG}` |
| `POST /v1/harmonize` | `{image, protect, mask?, strength}` | `{image}` |

תמונות מעובדות בזיכרון ולא נשמרות. `MOCK=1` – תוצאות דמה לבדיקת חיבור. `ALLOWED_ORIGIN` – הגבלת CORS. בפריסה: HTTPS + אימות/הגבלת קצב.

## מגבלות דיוק (בכנות)

* **זו הרכבה (compositing) דו־ממדית, לא רינדור תלת־ממדי.** המוצר הוא הפיקסלים שצולמו בחנות: אם זווית הצילום שונה מזווית החדר, הוא ייראה מעט "לא נכון" – לכן אפשר לצלם כמה זוויות ולבחור. אין "סיבוב" אמיתי של המוצר.
* **כיוון האור לא משתנה על המוצר עצמו** – אור שנפל משמאל בחנות יישאר משמאל. ההתאמה היא לחשיפה, לגוון, לניגודיות, לחדות ולרעש; הצל המוטל מכוון ידנית (או מהגרסה "אור מהחלון").
* **השתקפויות** (מראה, טלוויזיה כבויה, זכוכית) משקפות את החנות, לא את החדר.
* **SAM מאחד לפעמים קירות ותקרה** בחדר בצבע אחיד – לכן לקיר גוררים את ארבע הפינות (הזיהוי עדיין מוציא אוטומטית חלון, שידה וצמח). כתמי שמש על הרצפה מזוהים לעיתים כאזור נפרד – "הוספת אזור" בנגיעה.
* **רגליים דקות** של רהיטים עלולות להיחתך ב-AI (ISNet) – מחזירים במברשת "שחזור".
* **פרספקטיבת רצפה אוטומטית** מניחה צילום חזיתי של החדר (קווי הקיר-רצפה מתכנסים לנקודה אחת); צד מוסתר (צמח/רהיט) משוחזר בשיקוף. אפשר תמיד לגרור פינות.
* **הסתרה** מבוססת על "מי נמוך יותר בתמונה קרוב יותר" – נכון לרהיטים על אותה רצפה, לא לחפצים תלויים.
* **גודל אמיתי** מדויק רק בעומק שבו סומן קנה המידה/המישור.
* תוצאה מקומית אינה "פוטוריאליסטית" במובן של רינדור פיזיקלי; היא מסומנת תמיד "הדמיה להמחשה".
