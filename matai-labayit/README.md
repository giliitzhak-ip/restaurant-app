# מתאים לבית (שם זמני)

אפליקציית מובייל בעברית (RTL) שעוזרת לבחור מוצרים לבית תוך כדי סיבוב בחנויות:
מצלמים חדר, מצלמים מוצר בחנות (כל חנות – בלי קטלוג ובלי שיתוף פעולה), והמוצר מוצג על תמונת הבית
כדי לבדוק מראה, צבע, גודל ומיקום לפני הקנייה.

> כל הדמיה היא **להמחשה בלבד** – לא מדידה מדויקת ולא מציאות רבודה. האפליקציה מסמנת זאת במסך ובכל תמונה מיוצאת,
> ומציגה אזהרה "גודל משוער" כשאין מידות.

## שלושה תרחישים – מקור, מוצר, תוצאה

תמונות הבדיקה נוצרו ברינדור פיזיקלי (Mitsuba 3, [`tools/render_test_scenes.py`](tools/render_test_scenes.py)) כדי שיהיה גם

מה קרה בכל תרחיש (הצעדים שהבדיקה ביצעה במסכים עצמם):

1. **ספה:** "העלה תמונת חדר" ← בדיקת תמונה ← "צלם מוצר בחנות" + זווית נוספת מהגלריה ← מלבן סביב הספה ← "הסרת רקע AI"
   (ISNet+SAM; מדפים, כורסה ומנורה נשארו בחוץ) ← הצבה ושינוי גודל ← "מבנה החדר": נגיעה על שולחן הקפה + "+ חלק" לחלק המואר
   ולרגליים ← הספה מוסתרת מאחורי השולחן ← גרסה "מאוזן" ← ייצוא. המדידה הראתה שצילום החנות חשוך פי ~1.8 מהחדר; בגרסה "מאוזן" (40% השתלבות) הספה הובהרה בכ-25% – הצורה והפרטים לא השתנו.
2. **פרקט:** צילום לוח הדוגמה בחנות ← סימון הלוח ("יחידה", "ניקוי תאורת החנות") ← "זיהוי המשטח בנגיעה" על הרצפה (SAM) ←
   פרספקטיבה אוטומטית מקווי הקיר-רצפה (הפינה הימנית מוסתרת בצמח – שוחזרה בשיקוף) ← "הוספת אזור" על ארבעה כתמי שמש
   שהזיהוי השאיר בחוץ ← ייצוא. השולחן, השידה והעציץ נשארו מעל הפרקט, והאור והצל של החדר נשמרו.
3. **חיפוי:** צילום לוח הרפפות ← סימון ← "זיהוי המשטח בנגיעה" על הקיר ← גרירת 4 הפינות לפינות הקיר האחורי (SAM איחד את הקיר
   עם התקרה) ← ייצוא. החלון, השידה, האגרטל והצמח לא כוסו – אוטומטית מהזיהוי, בלי סימון ידני.

**הפער מה"אמת" (בכנות):** הספה צולמה בחנות מגובה אחר מזה של החדר, ולכן נראית מעט "חזיתית" מדי; רגל ימין דקה של הספה
לא זוהתה ע"י ה-AI (אפשר להחזיר במברשת "שחזור"); כתמי השמש על הפרקט יוצאים בהירים ולבנים יותר מבמציאות (אין חישוב אור
אמיתי); לוח הדוגמה בחנות קטן, ולכן דוגמת הפרקט חוזרת – "שונות טבעית" מרככת זאת אבל לא מבטלת; פינה קטנה של משטח
השולחן המואר לא זוהתה, ובה נראה קצה הצל של הספה (מתקנים ב"סימון במברשת"); החיפוי יוצא מעט בהיר מה"אמת" ועם
הבדלי גוון בין לוחות – אפשר להקטין ב"שונות טבעית" ובמחוון הנאמנות.

## הרצה מהירה

דרישות: Node.js 20+ (נבדק עם 22), npm. לטלפון: אפליקציית **Expo Go** (SDK 57), או Development Build.

```bash
cd matai-labayit
npm install              # מעתיק גם את canvaskit.wasm ל-public/ (נדרש רק לתצוגה בדפדפן)
npx expo start           # סרקו את קוד ה-QR עם Expo Go (אנדרואיד) או עם המצלמה (iPhone)
```

אפשרויות נוספות:

```bash
npx expo start --web     # תצוגה מקדימה בדפדפן (מומלץ במצב מובייל ב-DevTools)
npm run build:web        # בנייה סטטית לדפדפן לתיקייה dist/
npm run typecheck        # בדיקת טיפוסים
npx expo run:ios         # Development Build מקומי (דורש Xcode) – או:
npx eas-cli@latest build --profile development --platform all   # בנייה בענן של Expo
```

* **עברית מימין לשמאל:** ב-Development Build ה-RTL נקבע מראש (`expo-localization` עם `forcesRTL` ב-`app.json`).
  ב-Expo Go האפליקציה מפעילה RTL בעצמה; ייתכן שבהפעלה הראשונה צריך לסגור ולפתוח אותה פעם אחת כדי שהכיוון יתעדכן.
* **שרת ה-AI (לא חובה):** `cd server && npm install && npm run models && npm start` (~350MB מודלים פתוחים, בלי מפתחות).
  באפליקציה: הגדרות ← "עיבוד בענן" ← כתובת השרת. בלי שרת – כל העורך עובד עם עיבוד מקומי. פירוט: [`CAPABILITIES.md`](CAPABILITIES.md).
* **נתוני הדגמה:** במסך הפתיחה "לנסות עם חדר לדוגמה", או בהגדרות ← "טעינת חדר לדוגמה". ההסרה בלחיצה אחת
  (הגדרות ← "הסרת נתוני ההדגמה"). כל ישויות ההדגמה מסומנות `demo: true`, והקבצים ב-`assets/demo/` הם איורים שנוצרו לפרויקט.

## ארכיטקטורה

הפרדה לפי שלבי הצינור:

| שלב | מודולים |
|---|---|
| צילום | `services/media.ts` (הרשאות, מצלמה/גלריה, שחזור צילום באנדרואיד, סיבוב/חיתוך), `components/PhotoReview.tsx`, `components/useDraft.ts`, `imaging/quality.ts` |
| חיתוך מוצר | `imaging/cutout.ts` (מקומי + הסרת צל חנות), `app/cutout/*`, שרת: `vision.removeBackground` |
| זיהוי משטחים וחפצים | `editor/roomTools.ts`, `imaging/geometry.ts` (מרובע רצפה מקווי הקיר), `regionGrow`, שרת: `vision.samSegment` |
| מנוע העורך | `editor/useDesignEditor.ts` (מצב, ביטול/ביצוע, שמירה), `editor/EditorCanvas.tsx` (מחוות), `editor/objectGeometry.ts` |
| שירות ההדמיה | `editor/Composition.tsx` (רינדור – אותו קוד לעורך, להשוואה ולייצוא), `editor/realism.ts` + `imaging/harmonize.ts` (התאמה לחדר), `editor/patterns.ts`, `editor/exporter.tsx` |

```
src/
  app/            מסכים (Expo Router) – ממשק משתמש בלבד
  components/     רכיבי UI נגישים (כפתורים, מחוון, דיאלוגים, טיפים)
  editor/         עורך ההדמיה: Composition (רינדור), EditorCanvas (מחוות), useDesignEditor
                  (מצב + ביטול/ביצוע מחדש + שמירה אוטומטית), panels/ (כלים לפי סוג), exporter (ייצוא)
  imaging/        עיבוד תמונה מקומי: הסרת רקע, זיהוי משטח לפי צבע, צבע, גאומטריה/הומוגרפיה
  services/       מצלמה/גלריה (הרשאות), שיתוף/גלריה, לקוח לשירות הענן
  storage/        db.ts (מאגר נתונים + מנוי לשינויים), imageStore (קבצים / IndexedDB)
  model/          טיפוסים וקטגוריות
  demo/           טעינה והסרה של נתוני הדגמה
server/           שרת AI אופציונלי: מודלים מקומיים (vision.js) + Proxy לספקים חיצוניים
tools/            יצירת תמונות הבדיקה (רינדור פיזיקלי)
test-images/      תמונות בדיקה: חדר, מוצרים בחנות, ותמונות "אמת"
```

**הפרדה:** מסכים לא ניגשים לאחסון או לפיקסלים ישירות; הם משתמשים ב-`storage/*`, `imaging/*` ו-`services/*`.
רכיב `Composition` "טהור" (מקבל תמונות טעונות) ולכן אותו קוד משמש לעורך, להשוואה ולייצוא ברזולוציה מלאה.

**מניעת אובדן עבודה:** כל שינוי בעורך נשמר מקומית תוך פחות משנייה, ובמעבר לרקע – מיד.
"שמירה" מעדכנת תמונה ממוזערת, "גרסה חדשה" משכפלת – הגרסה הקודמת לא נדרסת.

**פרטיות והרשאות:** הרשאת מצלמה מתבקשת רק כשלוחצים "צילום"; בחירה מהגלריה משתמשת בבוחר המערכת (בלי גישה לכל התמונות);
הרשאת שמירה לגלריה – רק כששומרים. תמונות לא נשלחות לשום שרת, אלא אם המשתמש הפעיל שירות ענן בהגדרות,
אישר את ההסבר, **וגם** לחץ על פעולת ענן (לתמונת חדר – אישור נוסף בכל פעם).

## איך נוצרת ההדמיה

1. **צילום:** בדיקת התמונה (סיבוב/חיתוך/החלפה + בדיקת איכות), כמה זוויות למוצר, טיוטה שנשמרת כל הזמן.
2. **חיתוך המוצר:** מקומי (צבע) או AI בשרת (ISNet + SAM). תיקון במברשת. צל הרצפה של החנות מוסר בחיתוך המקומי – הצל נוצר מחדש בחדר.
3. **מבנה החדר:** מישורי קיר/רצפה (ארבע פינות, אופציונלית מידות) וחפצים קיימים (נגיעה/מברשת). זיהוי אוטומטי כשיש שרת, ידני תמיד.
4. **הצבה:** פרספקטיבה (הטיה, ארבע פינות, או הצמדה למישור), גודל ממידות/קנה מידה.
5. **השתלבות:** חשיפה, איזון לבן, ניגודיות, חדות וגרעיניות לפי מדידה של שתי הסצנות – בעוצמה שנקבעת במחוון
   "נאמנות למוצר המקורי ↔ שיפור השתלבות". הצורה והפרטים של המוצר לא משתנים; לא "ממציאים" חלקים.
6. **צל והסתרה:** צל מגע + צל מוטל מצללית המוצר; מוצר שמאחורי רהיט שסומן מוסתר; "מברשת הסתרה" לכל השאר.
7. **משטחים:** דוגמה בפרספקטיבה מלאה, שונות בין לוחות, שמירת האור והצללים של החדר, פתחים וחפצים לא מכוסים.
8. **בחירה:** ארבע גרסאות מוכנות, לפני/אחרי, השוואה, גרסאות שמורות, ייצוא.

**מה זה לא:** לא רינדור תלת־ממדי ולא מודל שמייצר את המוצר מחדש. זו הרכבה של הפיקסלים האמיתיים שצולמו, עם תיקוני
צבע, צל והסתרה. לכן זה לא מוצג כ"הדמיה פוטוריאליסטית" אלא כ"הדמיה להמחשה". מודל יצירת תמונה (אם יחובר) מוגבל
בשרת לסביבה ולצל – פיקסלי המוצר מוחזרים למקומם אחרי העיבוד.

## מה נבדק בפועל

נבדק בדפדפן Chromium (Playwright, מסך טלפון 390×844) על השרת של Expo, עם העלאת קבצים אמיתית דרך כפתורי האפליקציה,
ועם שרת ה-AI המקומי (המודלים האמיתיים):

1. **שלושת התרחישים** שלמעלה, מקצה לקצה – מהעלאת החדר ועד קובץ הייצוא.
2. צילום: "צלם חדר"/"העלה תמונת חדר"/"צלם מוצר בחנות"/"העלה תמונת מוצר" (בדפדפן המצלמה נפתחת כבוחר קבצים),
   מסך בדיקת התמונה, סיבוב, זווית נוספת ובחירה ביניהן, טיוטה ששוחזרה אחרי טעינה מחדש של הדף.
3. חיתוך מקומי ו-AI, מברשות, הסרת צל החנות (ובדיקה שהיא לא פוגעת בחיתוך AI), הודעות על צילום בעייתי.
4. מבנה החדר: חפץ בנגיעה (AI), "+ חלק" (משטח מואר ורגליים), הגנה מבחירה שגויה של כל הרצפה, הסתרה בפועל בייצוא.
5. משטחים: זיהוי רצפה וקיר ב-AI, מרובע רצפה אוטומטי, "הוספת אזור", פינות, התאמת חשיפה, שונות בין לוחות.
6. מה שנבדק בגרסה הקודמת: עורך (גרירה, ביטול/ביצוע, גרסאות), צבע קיר, אריחים, תאורה, השוואה, ייצוא, רשימת קניות,
   נתוני הדגמה, מחיקת נתונים, והשרת במצב דמה.
7. `npm run typecheck`, ובשרת `npm test` (כולל הרצת SAM/ISNet/MiDaS על תמונה).

**לא נבדק בסביבה הזו:** מכשיר iPhone/אנדרואיד פיזי או אמולטור (אין בסביבה), מצלמה אמיתית ושחזור צילום אחרי שהמערכת סגרה
את האפליקציה (הקוד קיים – `recoverPendingCapture`), גיליון השיתוף ושמירה לגלריה בטלפון, remove.bg עם מפתח אמיתי,
ושירות "השתלבות" גנרטיבי (לא חובר מודל). מומלץ לעבור על הזרימה ב-Development Build בטלפון לפני הפצה.
