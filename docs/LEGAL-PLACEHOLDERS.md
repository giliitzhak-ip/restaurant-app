# פרטים משפטיים ועסקיים שחסרים

**מקור האמת בקוד:** `src/config/legal.ts`
**בדיקה:** `npm run compliance:check` מדפיס את המצב העדכני.

---

## למה הפרטים האלה ריקים

אף אחד מהם אינו ניתן לגזירה מהקוד. ח.פ., כתובת רשומה, שם ספק הסליקה, האם נדרש ממונה
הגנת פרטיות — כל אלה מגיעים מהעסק.

היה אפשר למלא אותם בערכים סבירים למראה. זו הייתה הטעות היקרה ביותר במסמך הזה: **ח.פ.
מומצא בתקנון הוא מצג שווא לצרכן**, ומספר טלפון שנראה אמיתי אך אינו עונה גרוע מהיעדר מספר.

לכן פרט שלא סופק שווה `null`, והאתר מציג במקומו **"— טרם הושלם —"** בצורה גלויה. גם
`compliance:check` חוסם ערכים שנראים מומצאים (`000000`, `example.com`, `12-3456789`).

בסביבת production מודפסת אזהרה בעת עליית התהליך, עם ספירת הפריטים החוסמים.
היא **אזהרה ולא כשל**: ח.פ. חסר הוא חשיפה משפטית, לא חור אבטחה, ואתר שמסרב לעלות בגללו
אינו עוזר לאיש.

## חוסמי השקה (16)

אין להפעיל את האתר למכירה אמיתית בלי אלה.

### זהות העוסק

| מפתח | מה נדרש |
| --- | --- |
| `companyLegalName` | השם כפי שרשום ברשם החברות או ברשות המסים. |
| `companyId` | ח.פ. או ע.מ. **אין להמציא מספר.** |
| `companyIdKind` | חברה בע״מ / עוסק מורשה / שותפות. משפיע על נוסח התקנון. |
| `registeredAddress` | הכתובת הרשמית. הכתובת ב-`brand.ts` היא placeholder לתצוגה ואינה מאומתת. |

### יצירת קשר

| מפתח | מה נדרש |
| --- | --- |
| `phone` | המספר ב-`brand.ts` (`03-0000000`) אינו מספר אמיתי. |
| `email` | `hello@example.com` הוא placeholder. |
| `supportEmail` | היעד לבקשות ביטול ולפניות שירות. |
| `openingHours` | שעות פעילות. אם יש קבלת קהל — לציין גם אותה. |

### מסחר

| מפתח | מה נדרש |
| --- | --- |
| `returnsAddress` | כתובת למסירת הודעת ביטול ולהחזרת מוצרים. חובה לפי חוק הגנת הצרכן. |

| `deliveryTime` | טווח ימי עסקים **בפועל**. המספרים המוצגים כיום מגיעים מנתוני ה-seed ואינם התחייבות. |

## תלויי נסיבות (8) — **היעדר נתון אינו פטור**

לכל אחד מאלה התחולה תלויה בנתון שאינו קיים בפרויקט. הקוד **אינו מניח** פטור.

| מפתח | במה זה תלוי | מי מכריע |
| --- | --- | --- |
| `accessibilityCoordinator` | סוג העסק ומספר העובדים | מורשה נגישות |
| `physicalAccessibility` | האם יש קבלת קהל | מורשה נגישות |
| `databaseController` | מבנה הבעלות; וגם האם נדרשת הודעה או רישום של המאגר | עו״ד |
| `privacyOfficer` | היקף וסוג המידע לפי תיקון 13 | עו״ד |
| `installationLeadTime` | רלוונטי רק אם שירות ההתקנה מופעל | בעלים |
| `analyticsProvider` | ברירת המחדל היא ללא אנליטיקה כלל | בעלים |
| `emailProvider` | מי שולח בפועל; נדרש הסכם עיבוד מידע | בעלים + עו״ד |
| `crmProvider` | אם פניות מנוהלות במערכת חיצונית שמקבלת מידע אישי | בעלים + עו״ד |

## איך ממלאים

```ts
// src/config/legal.ts
companyId: {
  label: "ח.פ. / ע.מ.",
  value: "51-1234567",      // ← הערך האמיתי, ורק הוא
  note: "...",
  required: "launch",
},
```

לאחר מכן:

```bash
npm run compliance:check   # הספירה יורדת
npm run build              # האזהרה נעלמת כשהרשימה מתרוקנת
```

**אין צורך לגעת בשום עמוד.** כל הדפים המשפטיים, ה-footer וטופס הביטול קוראים מכאן.

## גרסאות המסמכים

`legalDocuments` ב-`legal.ts` מחזיק גרסה ותאריך לכל מסמך. **הגרסה נשמרת בכל רשומת
הסכמה**, כך שלשאלה "לאיזה נוסח הלקוח הזה הסכים" יש תשובה גם אחרי שני עדכונים.

כל הגרסאות כיום נושאות `draft`, ו-`compliance:check` **נכשל** אם ה-`draft` יוסר.
זה מכוון: הסרת הסימון מרמזת על בדיקה משפטית שטרם התקיימה. כשעו״ד יאשר נוסח —
מעדכנים את הגרסה **ומסירים את הבדיקה במודע**, בקומיט נפרד שאומר מי אישר ומתי.
