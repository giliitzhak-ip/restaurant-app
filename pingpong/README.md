# פינג פונג תלת־ממד · Ping Pong 3D

משחק טניס שולחן תלת־ממדי לדפדפן: TypeScript + Three.js + React, עם שרת Node.js סמכותי (authoritative) ומשחק בזמן אמת ברשת דרך WebSocket.

## מה יש במשחק

- **סימולטור:** המחשב משחק נגד עצמו ואתה צופה. בוחרים רמת קושי לכל צד, משנים מהירות (0.25x עד 4x, כולל הילוך איטי), מחליפים מצלמה (שידור, צד, מלמעלה, שחקן) ועוקבים אחרי נתונים חיים: מהירות כדור ומהירות שיא בקמ״ש, ספין בסל״ד, רצף חבטות ואיך הסתיימו הנקודות.
- **מצבים:** משחק מול מחשב (קל / בינוני / קשה), שחק עם חבר בחדר פרטי ברשת, אימון חופשי, ומגרש אימון עם הדרכה בת 6 שלבים. ההדרכה מוצעת אוטומטית לפני המשחק הראשון.
- **חוקים:** משחק עד 11 עם הפרש של 2, החלפת מגיש כל 2 נקודות, ומ־10:10 בכל נקודה. ההגשה חייבת לנחות קודם בצד המגיש ואז בצד היריב. הגשה שנוגעת ברשת ונוחתת כחוק היא Let וחוזרת. מטופלים גם כדור בחוץ, שתי קפיצות, פגיעה בצד שלך, חבטה לפני ניתור (volley), חבטה כפולה וכדור שנעצר. אפשר לבחור משחק בודד או הטוב משלושה.
- **פיזיקה:** כבידה, גרר אוויר ריבועי ואפקט מגנוס, וניתור עם חיכוך שמצמיד סיבוב למהירות: Topspin "בועט" קדימה ו־Backspin נבלם. הצעד קבוע, 240Hz, וכל ההתנגשויות (שולחן, דפנות, רשת, רצפה, מחבט) נבדקות כ־**Swept collision**. לכן גם כדור במהירות 40 מ'/ש' לא עובר דרך עצמים.
- **שליטה:** זווית הפנים של המחבט קובעת אם הכדור יעלה גבוה או ינמיך. תנופה לצדדים ופגיעה מחוץ למרכז המחבט מכוונות ימינה ושמאלה. מהירות התנופה ומקש העוצמה קובעים את הקצב. יש Topspin ו־Backspin, וגם סיבוב הכדור הנכנס משפיע על המסלול.
- **שני מצבי סיוע:** **Arcade** (ברירת המחדל) מוסיף סיוע מתון בגובה, ברדיוס הפגיעה ובתיקון מסלול. **מתקדם** נותן הרבה פחות סיוע, כך שקל יותר לטעות.
- **יריב ממוחשב:** יש לו זמן תגובה, מהירות תנועה מוגבלת, טעויות מיקום, "טעויות גסות" מזדמנות ורעש ביצוע שגדל מול כדור מהיר. הוא לא מושלם בשום רמה.
- **גרפיקה:** אולם עם רצפת עץ, משטח קורט, מחסומים, יציעים ותאורת תקרה. השולחן בממדי ITTF, עם רשת, עמודים ומחבטים. יש צללים, ניטור דינמי של סביבה (בהגדרות High ו־Ultra) ו־ACES tone mapping. **הכדור תמיד בולט:** חומר זוהר, הילה, שובל, צל־כתם וגודל מינימלי על המסך.
- **איכות:** Low / Medium / High / Ultra. ב־Ultra הרינדור מגיע עד **‎3840×2160** (4K אמיתי במסך 4K, או רינדור 4K מוקטן במסך 1080p). רזולוציה דינמית מורידה ומעלה את רזולוציית הרינדור כדי לשמור על כ־60FPS.
- **ממשק:** עברית מלאה ב־RTL, עם מעבר לאנגלית. ה־HUD מציג ניקוד, מגיש, מצב חיבור ו־Ping. יש ספירה לאחור, הודעות סיבת נקודה, מסך ניצחון, משחק חוזר, מסך מלא, השהיה, והודעה לסובב את המכשיר לרוחב בנייד.
- **הגדרות:** עוצמת קול, רגישות שליטה, איכות גרפית, רזולוציה דינמית, הפחתת אפקטים ותנועה, הצגת FPS, פריסת מגע לשמאליים ושפה.
- **צלילים:** חבטת מחבט, שולחן, דופן, רשת ורצפה. כל צליל שונה ומסונתז בזמן אמת, ויש גם מחיאות כפיים בניצחון.

## שליטה

| התקן | פעולה |
|---|---|
| עכבר | הזזה: המחבט עוקב אחרי הסמן במישור המחבט · כפתור שמאלי (החזקה): Topspin · כפתור ימני (החזקה): Backspin · גלגלת: זווית המחבט · Shift: עוצמה · קליק: הגשה |
| מקלדת | חצים/WASD: הזזה · Q/E: זווית · Z: Topspin · X: Backspin · Shift: עוצמה · רווח/Enter: הגשה · Esc: השהיה |
| מגע (נייד) | גרירה ב**אזור מגע ייעודי** בפינה, כך שהאצבע לא מסתירה את הכדור · כפתורי הגשה, Top, Back ועוצמה · מחוון זווית |

התנועה קדימה ואחורה (footwork) אוטומטית. השחקן שולט במיקום לרוחב ובגובה. המצלמה נמצאת מאחורי הצד שלך, ובמהלך נקודה היא יציבה ונעה רק מעט לצדדים.

## התקנה והרצה

נדרש Node.js 20 ומעלה (נבדק על Node 22).

```bash
cd pingpong
npm install

# פיתוח: שרת המשחק (8080) + Vite (5173) עם proxy ל-/ws
npm run dev
# פתח http://localhost:5173

# Build מלא: בדיקת TypeScript + לקוח + שרת
npm run build

# הרצת פרודקשן: שרת אחד מגיש גם את הלקוח וגם WebSocket
npm start
# פתח http://localhost:8080   (בריאות: /healthz)
```

משתני הסביבה מתועדים ב־[`.env.example`](.env.example). אין בו סודות.

### גרסת הדגמה בלי שרת

```bash
npm run build:demo   # dist/standalone: סימולטור, משחק מול מחשב ואימון. בלי משחק ברשת
```
בגרסה הזו כפתור "שחק עם חבר" מוסתר, כי אין שרת להתחבר אליו.

## ארכיטקטורה

```
src/shared/     לוגיקה משותפת ללקוח ולשרת (TypeScript טהור, בלי DOM)
  physics.ts      מנוע פיזיקה: אינטגרציה, Swept collision, ניתור עם ספין
  paddle.ts       קלט שחקן, בקר מחבט, חיזוי נקודת פגיעה, פרופילי סיוע
  shot.ts         מודל המכה וההגשה, ופותר מסלול (shooting method)
  rules.ts        ניקוד, החלפת הגשות, שוויון, הטוב מ-3, שופט נקודה
  game.ts         GameSim: מכונת מצבים של משחק (countdown/serve/rally/point/...)
  ai.ts           יריב ממוחשב: מפיק PaddleInput בדיוק כמו שחקן אנושי
  protocol.ts     הודעות רשת ואימות קלט
src/server/     שרת Node.js: HTTP סטטי + WebSocket, חדרים, הגבלת קצב
src/client/
  render/         Three.js: אולם, שולחן, מחבטים, כדור, איכות, רזולוציה דינמית
  input/          עכבר / מקלדת / מגע -> PaddleInput
  net/            NetClient (חיבור מחדש, ping) ו-OnlineSession (חיזוי, תיקון, אינטרפולציה)
  game/           LocalSession: אותו GameSim עם AI, מקומי
  audio/          צלילים מסונתזים ב-Web Audio
  ui/             React: תפריטים, לובי, HUD, מגע, הדרכה
```

ההפרדה בין השכבות: **פיזיקה** (`physics.ts`), **חוקים** (`rules.ts`), **רינדור** (`render/`), **קלט** (`input/`) ו**רשת** (`net/` + `server/`). אותו `GameSim` רץ במשחק יחיד בדפדפן ובשרת במשחק רשת, ולכן ההתנהגות זהה בשני המצבים.

### משחק ברשת: החלטות תכנון

- **השרת הוא מקור הסמכות היחיד** לפיזיקה, למכות, להגשות, לנקודות ולתוצאה. הלקוח שולח רק כוונות: מיקום מחבט רצוי, זווית, ספין, עוצמה ומונה הגשה. כל ערך מאומת ומוגבל לטווח (`sanitizeInput`). הודעה מכל סוג אחר, למשל ניסיון לשלוח ניקוד, נדחית עם `BAD_MESSAGE`.
- **קצבים:** הפיזיקה רצה ב־240Hz. השרת מתקדם ב־tick של 120Hz (2 צעדי פיזיקה בכל tick), שולח snapshot ב־60Hz, והלקוח שולח קלט ב־60Hz. הבחירה נובעת מכך שכדור פינג פונג חוצה את השולחן בכ־0.25–0.4 שניות. 60 עדכונים בשנייה נותנים 15–25 דגימות לכל מעבר, עם חבילה של כ־400 בתים בלבד (כ־24KB/s לשחקן). ה־240Hz בפיזיקה, יחד עם הבדיקה הרציפה, מונעים מכדור מהיר לעבור דרך עצמים.
- **מספרי רצף לקלט:** כל snapshot כולל `ack`, מספר הקלט האחרון שהשרת יישם לכל שחקן. קלט ישן או משוכפל נזרק. אם מצטבר תור (lag spike), נשמרים רק 6 הקלטים האחרונים.
- **חיזוי מקומי ותיקון:** המחבט שלך זז מיד לפי אותו בקר מחבט משותף. כשמגיע snapshot, הלקוח חוזר למצב המחבט אצל השרת ומריץ מחדש את הקלטים שעוד לא אושרו (reconciliation). הפער מוסתר בהחלקה קצרה של כ־80ms.
- **אינטרפולציה:** הכדור והיריב מוצגים מעט בעבר, בין שני snapshots. ההשהיה מסתגלת לג'יטר שנמדד, בטווח 40–150ms. אירועים כמו צלילים מוצגים בזמן ה־snapshot שלהם, כך שהם מסונכרנים לתמונה.
- **סבולת להשהיה:** פגיעה נקבעת לפי מיקום המחבט כשהכדור חוצה את מישור המחבט, ולא לפי תזמון לחיצה. המשמעות היא שאפשר למקם את המחבט מראש, וזה עובד היטב גם עם Ping של 100–200ms.
- **ניתוק:** המשחק נעצר והיריב רואה ספירה לאחור. המקום שלך שמור 60 שניות. הלקוח מנסה להתחבר מחדש אוטומטית (backoff), ותוך כדי כך גם רענון דף מחזיר אותך לחדר (טוקן ב־sessionStorage). אחרי חזרה **הנקודה שנקטעה משוחקת מחדש**, בלי ניקוד על הניתוק. אם השחקן לא חוזר בזמן, החדר חוזר ללובי ונשלחת הודעה ליריב.
- **הגנות:** גודל הודעה עד 2KB. הגבלת קצב לכל חיבור (token bucket 75/s, burst 90), וניתוק אחרי הפרות חוזרות. עד 10 חיבורים לכל IP, ועד 12 חדרים חדשים לדקה לכל IP. רשימת Origins מותרים (אופציונלית). heartbeat מנתק חיבורים מתים. חדר שהתרוקן נסגר, ולובי ללא פעילות נסגר אחרי 30 דקות. חדר מוגבל לשני שחקנים, ויש הודעה ברורה כשחדר מלא (`ROOM_FULL`) או לא קיים (`ROOM_NOT_FOUND`).

## פריסה לאינטרנט (HTTPS / WSS)

משחק עם חברים חייב שרת שנגיש מהאינטרנט. **הפרויקט עדיין לא פורסם**, כי לא הוגדר עבורו שירות אירוח (ראו "מה עדיין דורש חיבור חיצוני" בהמשך).

החדרים נשמרים בזיכרון, ולכן צריך **מופע שרת אחד**. כשהשרת גם מגיש את הלקוח (מקור אחד), הלקוח מתחבר אוטומטית ל־`wss://<הדומיין>/ws` ואין צורך להגדיר כתובת שרת.

### אפשרות א': Render.com (הכי פשוט)
1. ב־Render בחר New → Blueprint וחבר את המאגר. הקובץ [`render.yaml`](render.yaml) מגדיר שירות Docker מתוך התיקייה `pingpong/`.
2. Render מספק HTTPS ו־WSS אוטומטית. הכתובת תהיה בסגנון `https://pingpong-3d.onrender.com`, והמשחק מתחבר ל־`wss://…/ws`.
3. בתוכנית החינמית השרת "נרדם" כשאין פעילות. לכן נבחרה תוכנית `starter`.

### אפשרות ב': Fly.io
```bash
cd pingpong
fly launch --copy-config --no-deploy   # שנה את שם האפליקציה ב-fly.toml
fly deploy
```
`force_https` פעיל ו־WSS עובד אוטומטית. השאר `min_machines_running = 1` ומכונה אחת בלבד.

### אפשרות ג': שרת משלך (VPS) עם Docker
```bash
docker build -t pingpong-3d pingpong/
docker run -d -p 8080:8080 -e TRUST_PROXY=1 --restart unless-stopped pingpong-3d
```
מומלץ להפעיל מאחורי Caddy, שמנפיק אישור TLS אוטומטית ומעביר WebSocket:
```
pingpong.example.com {
    reverse_proxy 127.0.0.1:8080
}
```
אפשר גם להפעיל TLS ישירות ב־Node: `TLS_CERT_FILE=/path/fullchain.pem TLS_KEY_FILE=/path/privkey.pem npm start`. במקרה הזה השרת מאזין ב־HTTPS/WSS. האפשרות נבדקה עם אישור self-signed באמצעות `npx tsx scripts/wss-check.ts cert.pem key.pem`.

### אפשרות ד': לקוח סטטי ושרת נפרדים
```bash
VITE_SERVER_URL=wss://game-server.example.com/ws npm run build:client
# העלה את dist/client לכל אירוח סטטי (Netlify, Vercel, GitHub Pages, S3...)
# בשרת: ALLOWED_ORIGINS=https://your-static-site.example npm start
```

- ✅ WSS: השרת במצב TLS נבדק עם אישור self-signed.
- ✅ Dev proxy של Vite ל־`/ws` נבדק. התקנת פרודקשן (`npm ci --omit=dev`) והרצה מ־`dist/` נבדקו.

## מה לא נבדק / מגבלות

- ❌ **לא בוצעה פריסה לאינטרנט, ואין קישור ציבורי.** משחק בין שני מכשירים ברשתות שונות דרך WSS ציבורי לא נבדק, כי בסביבת העבודה לא הוגדר שירות אירוח לפרויקט. שתי לשוניות או הקשרים מקומיים הם בדיקת פיתוח בלבד.
- ❌ לא נבדק על **מכשיר נייד אמיתי** ולא על **GPU אמיתי**. הבדיקה החזותית נעשתה ב־Chromium headless עם רינדור תוכנה, שם קצב הפריימים נמוך (15–30FPS ברזולוציה מוקטנת). מספרי ה־FPS האלה לא מייצגים מחשב או טלפון רגילים. 60FPS הוא יעד, לא הבטחה.
- ❌ לא נבדקו Safari או Firefox. אין מקום לשמע אמיתי בסביבת הבדיקה, כך שהצלילים לא נשמעו בפועל: הם נבנו ונבדקו רק ברמת הקוד.
- ❌ `docker build` לא הורץ: אין Docker daemon בסביבה. במקום זאת נבדקו אותם שלבים ידנית (build, `npm ci --omit=dev`, הרצה).
- מגבלה: החדרים בזיכרון של מופע יחיד. כדי להריץ כמה מופעים צריך sticky routing לפי קוד חדר או אחסון משותף.

## מה עדיין דורש חיבור חיצוני

1. חשבון בשירות אירוח (Render / Fly.io / VPS עם דומיין) ופריסה לפי ההוראות למעלה.
2. אם הלקוח מתארח בנפרד: הגדרת `VITE_SERVER_URL=wss://…/ws` בזמן build, והגדרת `ALLOWED_ORIGINS` בשרת.

## מקור הנכסים (Assets)

כל הנכסים מקוריים ונוצרים בקוד המקור של הפרויקט:
- **טקסטורות** (משטח השולחן עם קווים, רצפת עץ, משטח הקורט, רשת, מחסומים, קירות, הילה וצל): מצוירות בזמן ריצה על Canvas (`src/client/render/textures.ts`).

- **אייקון:** SVG מקורי (`public/favicon.svg`).
- **סביבת השתקפויות:** `RoomEnvironment` מתוך דוגמאות Three.js (רישיון MIT).
- **ספריות:** three (MIT), react ו־react-dom (MIT), ws (MIT).
